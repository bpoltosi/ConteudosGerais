Teste 3 - comando "ping 192.168.1.1" (ping para dispositivo em outra sub-rede)

Demonstração prévia de sub-redes distintas:
Host local: IP 172.22.72.78 com máscara 255.255.255.0 (/24).
Rede local: 172.22.72.0/24 (faixa de hosts: 172.22.72.1 a 172.22.72.254).
Host de destino: IP 192.168.1.1 com máscara /24 pertenceria à rede 192.168.1.0/24.
Como os identificadores de rede (NetID) são diferentes (172.22.72.0 != 192.168.1.0), o computador determina que a entrega deve ser indireta, enviando os pacotes ao Gateway Padrão.

a) Houve resolução de endereço pelo protocolo ARP? Para qual endereço IP?
R: 
Não houve resolução ARP para o IP 192.168.1.1.
O protocolo ARP opera exclusivamente no domínio de broadcast da rede local.
Computadores nunca disparam ARP buscando o MAC de um endereço IP pertencente a outra sub-rede.
Como o MAC do gateway já estava no cache ARP, não houve emissão de ARP.

b) Quais eram os endereços de destino na camada física (Ethernet/MAC) e na camada lógica (IP) do pacote enviado? 
R:
Camada Lógica (IP de Destino): 192.168.1.1 (o destinatário final do pacote).
Camada Física (MAC de Destino): 16-cb-8c-7c-80-78 (o endereço físico da interface do Gateway Padrão).

c) Consultando a tabela ARP, a quem pertenciam os endereços indicados no item anterior? 
R: 
O endereço IP pertencia ao host final de destino localizado na rede remota.
O endereço MAC pertencia ao Gateway Padrão (172.22.72.1), responsável por receber o quadro na camada de enlace, desencapsulá-lo e roteá-lo para fora da rede local.

d) Houve sucesso na resposta ao pacote?
R: Não. Ocorreu 100% de perda (4 pacotes enviados e 0 recebidos), com a mensagem "Esgotado o tempo limite do pedido", pois o endereço de destino não era alcançável a partir da rota externa ou não respondeu a requisições ICMP.

O computador descobre enviando um pacote "Standard Query" direcionado ao servidor DNS configurado na interface (2804:1f38:2001:a0::10).
O servidor processa e retorna um pacote "Standard Query Response":
Consulta: Identificada na captura (Transaction ID 0x9b3d) requisitando registro AAAA de www.ufsm.br.
Resposta: Registrada no Frame 28 (comprovada na captura "RbP4.PNG"), onde o servidor responde com: "www.ufsm.br: type AAAA, addr 2804:1f38:0:30::1950".

R: Sim, houve 100% de sucesso no teste (0% de perda). O tempo de resposta foi de 1 ms (mínimo, máximo e média iguais a 1 ms).

O comando exibe a tabela de cache DNS mantida pelo resolver do Windows. No resultado (conforme tela "ReP4.PNG"), constam as entradas recentemente consultadas para "www.ufsm.br", incluindo o Registro A (IPv4 200.18.47.118) e o Registro AAAA (IPv6 2804:1f38:0:30::1950), acompanhados de seus tempos de vida restantes (TTL).
